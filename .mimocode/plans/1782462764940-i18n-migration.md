# i18n Migration Plan — Move All Hardcoded Strings to i18n

## Overview
Migrate ~165 hardcoded user-facing strings across 20 Python files into 7 new JSON locale files + extend the existing `music.en.json`. Uses the existing `python-i18n` library (`from i18n import t`, `%{variable}` interpolation).

---

## New JSON Files to Create

All in `neonbot/lang/`:

| File | Source files |
|------|-------------|
| `common.en.json` | `embed.py`, `bot.py`, shared strings |
| `administration.en.json` | `cogs/administration.py` |
| `search.en.json` | `cogs/search.py` |
| `utility.en.json` | `cogs/utility.py`, `utils/functions.py` |
| `event.en.json` | `cogs/event.py`, `classes/voice_events.py`, `decorators.py` |
| `panel.en.json` | `cogs/panel.py` |
| `exchange_gift.en.json` | `cogs/exchange_gift.py`, views, `classes/exchange_gift.py` |

## Existing File to Extend

- `music.en.json` — add ~12 keys for strings currently hardcoded in music/player files

## Strings to SKIP

- **Slash command `description` params** — Discord requires these at registration time; cannot be per-user locale
- **`log.*()` calls** — developer-facing, not user-facing
- **Internal traceback labels** — `'Traceback Exception'` stays hardcoded (but the user-facing error message at `event.py:178` IS migrated)

## Key Naming Convention

- `snake_case`, flat or 1-level nested
- Namespace = filename: `t('administration.prefix_set', prefix=...)`
- Plurals: `zero/one/many` sub-keys (existing pattern)
- No prefix redundancy inside namespace files
